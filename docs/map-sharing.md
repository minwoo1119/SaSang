# 지도 공유 내보내기

## 결과물

- 사진: 1080 × 1920 PNG
- 영상: 720 × 1280, 12 fps, H.264 MP4
- 두 결과물 모두 현재 지도 모드의 방문 수와 정수형 방문 비율을 표시한다.
- 사진 하단 진행 바는 현재 지도에서 실제로 방문한 비율만큼만 채운다.
- 내보내기 완료 후 `사진 보관함에 저장`과 `다른 앱으로 공유` 중 하나를 선택한다.
  앱이 먼저 자동 저장하지 않으므로 공유 시트에서 다시 저장해 중복되는 문제가 없다.

## 타임라인 순서와 모션

사진의 `takenAt`을 우선 사용하고, 촬영일이 없으면 `createdAt`을 사용한다. 동일한
날짜는 생성 시각과 지역 키로 안정적으로 정렬한다.

각 기록은 다음 순서로 렌더링한다.

1. 가장 오래된 사진의 지역을 먼저 확대하고 사진을 채운다.
2. 첫 지역에서 다음 지역으로 경로 선과 비행기가 이동한다.
3. 목적 지역의 실제 크기에 맞춰 지도를 확대한다.
4. 지역 폴리곤 안에 원본 사진과 저장된 crop transform을 적용해 사진을 채운다.
5. 다음 지역으로 이동하고, 마지막에는 전체 지도와 누적 경로를 보여준다.

기록이 많을 때는 지역별 중간 프레임 수만 줄인다. 모든 지역과 사진은 날짜순으로
포함되며 생략하지 않는다.

## 인코딩 결정

지도, 경로, 비행기와 사진 채움 프레임은 Flutter Canvas로 렌더링한다. Flutter
프레임을 MP4로 묶는 부분만 프로젝트 소유의 네이티브 구현을 사용한다.

- Android: `MediaCodec` + `MediaMuxer`
- iOS: `AVAssetWriter`

FFmpeg 같은 대형 외부 엔진을 포함하지 않아 앱 용량과 라이선스 부담을 줄이고,
각 플랫폼의 하드웨어 H.264 인코더를 사용한다. 임시 PNG 프레임은 인코딩 후 삭제하고
완성된 MP4만 임시 디렉터리에 남겨 공유한다. 원본 사용자 사진은 수정하거나 삭제하지
않는다.

## 검증 범위

- 단위 테스트: 날짜순 정렬, 현재 지도 필터링, 방문 비율, 기록 수별 모션 프레임 수
- iOS 시뮬레이터 통합 테스트: 9:16 PNG 생성, 실제 H.264 MP4 생성, 비대칭
  4색 프레임의 네 모서리를 재추출해 좌우·상하 방향 보존 확인
- Android: APK 컴파일 검증. 출시 전 실제 Android 기기에서 제조사별 H.264 인코더와
  사진 보관함 저장 동작을 한 번 더 확인해야 한다.
