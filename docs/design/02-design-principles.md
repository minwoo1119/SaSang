# Sasang 디자인 시스템 원칙 제안

## 1. 문서 상태

- 단계: Phase 2-A 설계 제안
- 근거: `00-current-ui-audit.md`, `01-component-inventory.md`
- 범위: 원칙과 적용 규칙만 정의하며 Flutter UI 코드는 변경하지 않는다.
- 선행 조건: Phase 1 문서 PR #12가 `dev`에 병합된 뒤 이 문서의 상대 링크가 유효해진다.
- 온보딩: PR #10은 `dev`에 병합됐지만 Phase 2-B 실제 마이그레이션 대상에서는 제외한다.

## 2. 디자인 목표

Sasang의 디자인 시스템은 현재 화면을 새 앱처럼 바꾸는 리디자인이 아니다. 지도와 사진을 중심으로 한 화이트·블루 UI, 떠 있는 조작부, iOS에 가까운 부드러운 상호작용을 보존하면서 화면마다 임의로 생긴 차이를 역할 기반 규칙으로 정리한다.

성공 기준은 다음과 같다.

1. 같은 역할의 제목, 여백, 반경, 그림자, 상태가 같은 의미로 보인다.
2. 지도와 사진이 카드·아이콘·그림자보다 먼저 보인다.
3. iOS와 Android에서 같은 정보 구조와 브랜드를 유지하되 플랫폼 표준 접근성을 존중한다.
4. 기존 컴포넌트를 확장해 적용할 수 있고 전면 재작성 없이 단계적으로 이전할 수 있다.
5. 선택, 비활성, 오류 상태를 색 하나에만 의존하지 않는다.

## 3. 핵심 원칙

### 3.1 지도는 화면이 아니라 캔버스다

- Full-screen Map을 유지한다.
- 지도 위 도구는 Floating Overlay로 유지하며 하단 고정 도구 모음으로 이동하지 않는다.
- 기록 요약, 공유, 지도 선택, 검색, 확대/축소/초기화 버튼을 임의로 삭제하지 않는다.
- 도구 수를 줄여야 할 때는 기능 삭제가 아니라 가까운 기능의 시각 그룹화, 대비 완화, 펼침 상태 구분을 먼저 검토한다.
- 사진 클리핑, Polygon/MultiPolygon, 선택 경계, 저장된 crop transform을 변경하지 않는다.
- 지역 이름을 지도 위에 상시 노출해 사진을 가리지 않는다. 선택 지역 정보는 현재의 Floating Region Control에서 제공한다.

```text
┌──────────────────────── Full-screen Map ────────────────────────┐
│ [기록 요약]                         [공유] [지도 선택]          │
│ [검색 ....................................................]     │
│                                                                 │
│                    사진이 채워진 Polygon               [ + ]    │
│                                                      [ − ]     │
│                                                      [1:1]     │
│                                                                 │
│        [선택 지역 · 사진 정보 · 다음 행동]  ← Floating          │
│   [지도]                 [장소]                 [더보기]         │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 강조는 한 컴포넌트 안에서 최대 두 가지 신호만 쓴다

선택 상태에 배경, 테두리, 글자색, 체크 아이콘, 그림자를 모두 겹치지 않는다.

- 단일 선택 카드: `accent border + soft accent background`를 기본 조합으로 사용한다.
- 체크가 이해에 반드시 필요하면 배경 또는 글자색 강조 하나를 뺀다.
- 선택된 지도처럼 실제 콘텐츠 미리보기가 중요한 경우 `accent border + semantic selected label`을 사용한다.
- 파괴 작업은 destructive 색상과 명시적 동사로 표시하며 장식적 경고 아이콘을 자동 추가하지 않는다.

작은 일반 텍스트에는 장식용 `#007AFF`와 `#8E8E93`를 그대로 쓰지 않는다. 흰색 표면에서
각각 약 4.02:1, 3.26:1로 WCAG AA 4.5:1에 미달하므로 링크/강조 텍스트는
`accentText #0066CC`, tertiary 텍스트는 `tertiaryTextAccessible #636366`을 사용한다.
아이콘, 큰 텍스트, 비텍스트 선택선에는 기존 브랜드 accent를 유지할 수 있다.

### 3.3 카드는 역할을 설명할 때만 사용한다

모든 카드를 없애거나 같은 반경으로 통일하지 않는다.

| 카드 역할 | 보존할 차이 | 원칙 |
|---|---|---|
| Settings Group | 여러 행의 소속 | 흰 표면+얇은 테두리, 기본 그림자 없음 |
| Place Photo | 사진 자체가 주 콘텐츠 | 8dp 현행 유지 후 실기 검증, 약한 elevation 허용 |
| Map Preview/Selection | 선택 가능한 지도 단위 | 24dp, 선택 테두리, 2열 구조 유지 |
| Content/Product | 설명과 미리보기의 결합 | 22dp, 중첩 카드/배지 최소화 |
| Empty State | 다음 행동 안내 | 필요 최소 높이, 카드 안의 또 다른 대형 버튼 반복 금지 |

카드 안에 다시 카드, 큰 원형 아이콘, 그림자, 배지를 동시에 넣는 구성은 피한다. 구분선이나 여백만으로 그룹이 충분하면 내부 표면을 추가하지 않는다.

### 3.4 간격은 수학보다 리듬을 따른다

- 기본 리듬은 4dp 배수지만 6dp는 제목-설명처럼 시각적으로 가까운 관계에 허용한다.
- 터치 영역, 글줄 높이, 광학 정렬 때문에 필요한 2dp 보정은 예외 토큰으로 남긴다.
- 5, 7, 9, 11, 13, 14, 17, 18, 22, 26, 28처럼 목적이 불명확한 값은 가장 가까운 의미 토큰으로 이동한다.
- 화면 좌우 여백은 16, 20, 24 중 콘텐츠 성격에 따라 선택한다. 지도 overlay 16, 시트 20, 문서 24의 차이는 유지한다.

### 3.5 타이포그래피는 크기보다 역할로 선택한다

- 화면 이름, 시트 제목, 섹션 제목, 옵션 제목, 본문, 보조 설명, 캡션, 버튼의 8개 역할을 기본으로 한다.
- 같은 역할에서 21/22/23처럼 1dp 차이를 두지 않는다.
- 브랜드/온보딩 Display는 일반 화면 제목과 분리한다.
- 법적 문서 본문은 일반 `body`와 분리한 `legalBody` 16sp/line-height 1.68을 유지한다.
- 제목은 역할별로 w700~800을 사용한다. Display와 강한 Sheet 제목만 w800을 허용하고
  일반 Page/Section/Option 제목은 w700을 기본으로 한다.
- 한국어·일본어·중국어는 과도한 음수 letter spacing을 피하고, 영어도 동일한 의미 계층을 유지한다.
- 텍스트 배율을 막지 않는다. 최대 줄 수를 제한하면 대체 접근 경로 또는 높이 확장을 제공한다.

### 3.6 그림자는 떠 있음을 설명할 때만 쓴다

- 지도 위 Floating Control, Floating Bottom Navigation, 중앙 Dialog에는 elevation이 필요하다.
- 설정 그룹, 문서 정보 그룹처럼 배경 위에 정적으로 놓인 컨테이너는 border만 사용한다.
- 사진 카드에는 콘텐츠 분리를 위한 낮은 elevation을 허용하되 회전·두꺼운 프레임·강한 그림자를 동시에 쓰지 않는다.
- blur는 지도 가독성을 유지하는 표면에만 사용하고 저사양 Android에서 성능을 검증한다.

### 3.7 Bottom Sheet는 공통 껍질과 유형별 몸체로 나눈다

다섯 유형의 구조는 유지한다.

1. 지도 라이브러리 선택: 상단 부착형, 스크롤 그리드, 고정 footer
2. 사진/영상 내보내기 선택: compact 선택형, 결과 미리보기 행
3. 지역 사진 관리: 사진 중심 carousel, 상태별 높이
4. 날짜 선택: compact task형, 사진+시스템 date picker+action
5. 지도 상점 상세: compact detail형, 미리보기+설명+가격+CTA

공통화 대상은 배경, radius, barrier, drag handle, header padding, 제목 계층, close button, safe area다. 콘텐츠 높이와 footer, carousel, picker까지 하나의 레이아웃으로 강제하지 않는다.

Bottom Sheet의 공통 배경은 `color.surface #FFFFFF`다. 페이지 배경용 canvas 색을 시트에
대신 적용하지 않는다. 사진/영상 내보내기와 내 지도 시트의 현재 콘텐츠 구성, 9:16
미리보기, 2열 지도 카드와 sticky footer는 그대로 유지한다.

```text
공통 Shell
┌──────────── drag handle ────────────┐
│ Title / optional description    [×]│
├────────────────────────────────────┤
│ Variant body                       │
│  grid | choice rows | carousel     │
│  picker | product detail           │
├────────────────────────────────────┤
│ optional sticky footer             │
└────────────────────────────────────┘
```

### 3.8 Dialog는 의도에 따라 네 Variant로 구분한다

| Variant | 용도 | 기본 행동 |
|---|---|---|
| Information | 완료/빈 상태/단순 고지 | 단일 확인 또는 자동 닫힘 |
| Confirmation | 되돌릴 수 있는 중요 결정 | 취소+확인 |
| Destructive | 데이터 삭제 등 비가역 결정 | 취소+명시적 destructive 동사 |
| Progress | 내보내기/백업처럼 진행 중 차단 필요 | Toss 스타일 중앙 모달, 진행 상태, 임의 종료 제한 |

Progress는 기존에 결정한 Toss 스타일 중앙 모달을 유지한다. 모든 알림을 커스텀 카드로 바꾸지 않으며, 플랫폼 표준 Dialog를 유지할 경우에도 호출 API와 semantic variant는 통합한다.

### 3.9 플랫폼 차이는 동작에서 허용하고 브랜드 계층은 공유한다

- 색상, 타이포 역할, 간격, 반경, 컴포넌트 정보 구조는 iOS/Android 공통이다.
- back gesture, date picker의 접근성 동작, semantics, system share, keyboard/focus는 플랫폼 표준을 우선한다.
- Android에서도 iOS 모양을 복제하기 위해 Material 접근성을 훼손하지 않는다.
- `CupertinoAlertDialog`, `CupertinoDatePicker`, `LicensePage` 같은 표준 구성요소는 래퍼 수준에서 semantic variant를 제공하고 내부 재구현은 최소화한다.
- blur가 성능 또는 대비 기준을 충족하지 못하면 불투명도 높은 흰 표면으로 graceful fallback한다.

### 3.10 변화는 회귀 증거와 함께 단계적으로 적용한다

- 토큰 도입과 화면 외형 변경을 가능한 한 분리한다.
- 지도 overlay는 golden/위젯 테스트와 실제 기기 캡처를 모두 요구한다.
- 4개 언어, iOS/Android, 일반/큰 글꼴, 작은/큰 화면을 검증한다.
- 한 PR에서 모든 화면을 일괄 변경하지 않는다.

## 4. 보존 규칙

다음은 승인 없이 변경하지 않는다.

- Full-screen Map과 Floating Overlay 구조
- 지도 사진 클리핑, 선택선, 확대/이동/초기화
- Floating Bottom Navigation의 3탭 정보 구조
- 더보기의 그룹형 카드
- 내 지도의 2열 미리보기 카드
- 사진/영상 내보내기 선택 Bottom Sheet의 두 형식 구조
- 지역 사진 관리의 carousel과 대표 사진/날짜/삭제 기능
- Flutter 표준 `LicensePage`
- 장소 카드 8dp radius(실기 비교 전)
- PR #10 온보딩 코드(현재 병합 상태와 무관하게 Phase 2-B 제외)

지도 검색창은 일반 control radius 대상이 아니다. 기존 pill silhouette를 유지하며
`radius.search = radius.pill`로 명시한다. 장소 카드 8dp radius도 이번 Token Foundation
단계에서는 비교안 생성 없이 그대로 유지한다.

## 5. 명시적 개선 대상

- 사진이 없는 지역의 310dp 대형 빈 카드
- 확인창의 커스텀/시스템 혼재와 직접 호출 분산
- Bottom Sheet의 handle/header/close 규격 분산
- 닫기 버튼 34/36/44 및 radius 8/17/18 혼재
- 같은 계층 제목 21/22/23, 화면 제목 24/26/28/30 혼재
- 목적 없는 spacing과 회색 직접값
- 정적 카드에 적용된 불필요한 그림자
- 선택 상태의 3개 이상 중복 신호

## 6. 접근성 원칙

- 최소 터치 영역 44×44dp. 시각 크기가 34/38이어도 hit target은 44 이상으로 확장한다.
- 텍스트와 아이콘은 배경 대비 WCAG AA를 목표로 한다. 비활성 상태도 읽을 수 있어야 한다.
- 상태는 색상만으로 전달하지 않는다. 선택은 semantics와 border/label 중 하나를 병행한다.
- 애니메이션 감소 설정에서 scale/rotation을 줄이고 fade 또는 즉시 전환으로 대체한다.
- 동적 글꼴에서 버튼 텍스트를 ellipsis로 숨기기보다 높이 증가 또는 세로 action 배치를 우선한다.
- 지도 도구는 시각 레이블이 없어도 정확한 semantics label을 제공한다.

## 7. 설계 의사결정 순서

새 UI 또는 기존 UI 정비 시 다음 순서로 판단한다.

1. 지도/사진의 시각 우선순위를 보존하는가.
2. 기존 Variant로 해결 가능한가.
3. 상태를 두 개 이하의 신호로 설명할 수 있는가.
4. 카드나 그림자 없이도 계층이 성립하는가.
5. 네 언어와 큰 글꼴에서 확장되는가.
6. iOS/Android 표준 동작을 유지하는가.
7. 새 토큰이 정말 필요한가, 기존 의미 토큰의 예외인가.
