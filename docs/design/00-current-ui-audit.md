## 2. 요약 판단

현재 UI의 가장 강한 자산은 지도 자체를 화면의 중심에 두는 구조다. Full-screen Map 위에 상태 요약·검색·지도 선택·확대 도구를 Floating Overlay로 올리고, 지역 맥락 작업은 Bottom Sheet로 이어가는 흐름은 제품 원칙과 잘 맞는다. 사진을 행정구역 폴리곤 안에 직접 클리핑하는 표현, 사진 앨범의 대표 이미지와 날짜 정보도 제품 정체성을 분명히 한다.

반면 보조 화면은 카드, 둥근 캡슐, 그림자, 원형 아이콘을 반복해서 사용한다. 개별 요소는 정돈되어 있으나 한 화면에서 동시에 겹치면 모든 요소가 강조되어 정보 우선순위가 흐려진다. 특히 지도 상점, 장소 목록, 온보딩 비주얼 카드에서 “AI가 자동 생성한 앱 UI”처럼 보일 수 있는 과장된 카드화가 나타난다. 확인창은 커스텀 중앙 모달과 기본 Cupertino 알림이 혼재하며, 바텀시트도 반경 28/30, 닫기 버튼 34/36/44, 헤더 간격이 서로 다르다.

### 우선순위 정의

- **P0 — 구조 보존:** 기능 정체성 또는 핵심 조작을 훼손할 위험이 있어 리디자인 시 반드시 먼저 고정할 항목
- **P1 — 높은 개선:** 여러 화면에 반복되고 인지 부담·일관성에 직접 영향을 주는 항목
- **P2 — 보통 개선:** 국소적인 밀도, 타이포그래피, 장식 문제
- **P3 — 낮은 개선:** 기능에 영향이 적은 미세 조정

## 3. 반드시 유지할 구조

1. `MapScreen`의 Full-screen Map과 `RegionMapView`의 직접 제스처(탭, 핀치 확대, 이동)
2. 지도 위 Floating Overlay: 기록 요약, 공유, 지도 선택, 검색, 확대/축소/초기화
3. 선택 지역을 지도와 동시에 보여 주는 하단 Floating Region Control
4. 지역 사진 추가·앨범·공유 형식 선택을 맥락 안에서 완료하는 Bottom Sheet
5. 사진을 폴리곤 안에 클리핑하고 선택 경계를 파란 선으로 표시하는 `RegionMapPainter`
6. 지도/장소/더보기의 3탭 정보 구조와 화면 상태를 보존하는 `IndexedStack`
7. 기기 내 사진 보관, 촬영일, 대표 사진이라는 사진 중심 메타데이터

## 5. 교차 화면 평가

### 잘된 부분

- 지도와 사진이 주 콘텐츠이며, 도구는 가장자리 overlay로 물러나 있다.
- 흰색/중립 배경과 `#007AFF` 포인트 색이 명확하고 사진과 충돌하지 않는다.
- 주요 터치 대상은 대체로 38~66 높이로 충분하다.
- 지역 선택→사진 추가→날짜 확인→지도 반영→장소 목록이라는 흐름이 시각적으로 연결된다.
- 위험 작업의 system red, 선택 상태의 accent, 보조 텍스트의 회색 사용은 의미가 안정적이다.
- 긴 문서, 라이선스, 동적 텍스트 배율을 일부 고려한 구현이 있다.

### 불편하거나 불안정한 부분

- 같은 역할의 화면이 서로 다른 시스템을 쓴다: 확인창 2종, 시트 3종 이상, 닫기 버튼 4개 규격.
- 반경이 8, 11, 14, 15, 16, 17, 18, 19, 20, 22, 24, 28, 30, 34, 999로 세분화되어 역할보다 화면별 취향에 가깝다.
- 제목 21/22/23/24/26/27/28/30이 화면마다 새로 정의되어 계층 규칙이 약하다.
- 지도 화면의 Floating Surface 수가 많고, 더보기/상점/장소는 카드 중첩이 많다.
- `#52525B`, `#8E8E93`, `#B4B4BA`, `#C4C4C8` 등이 토큰 밖에서 반복되어 보조색 단계가 불명확하다.

### AI 자동 생성형 표현 평가

- **과장된 카드:** 온보딩 `_VisualCard`(270×250, 반경 32, 큰 그림자), 지역 사진 빈 카드(높이 310), 지도 상점의 카드 안 미리보기/배지/설명/가격, 장소 대형 사진 카드가 해당한다.
- **불필요한 아이콘:** 정렬 화살표는 방향 정보를 주지 못한다. 공유 옵션의 chevron은 행 전체가 이미 버튼임을 중복 표기한다. 온보딩 선택 체크는 배경·테두리·색상 변화와 중복된다.
- **중복 강조:** 파란 배경+파란 테두리+파란 글자+체크, 카드+그림자+테두리, 앱바 제목+본문 대형 제목이 반복된다.
- **일관성 없는 여백:** 공용 간격 토큰은 4/8/12/16/24/32지만 실제 5/6/7/9/10/11/13/14/17/18/20/22/26/28/30/36/40도 광범위하게 사용된다. 일부는 광학 보정이지만 체계가 문서화되지 않았다.
- **판단:** 전체가 AI 생성형인 것은 아니다. 지도 painter와 사진 중심 상호작용은 제품 고유성이 강하다. 문제는 보조 화면의 장식 패턴이 관성적으로 반복되는 데 있다.

## 6. 권장 개선 순서(후속 단계용)

1. P0 구조를 고정하고 지도 overlay 충돌 기준을 회귀 테스트로 만든다.
2. 확인창·바텀시트·닫기 버튼·주요 버튼의 역할별 규격을 통합한다.
3. 타이포그래피와 반경을 의미 기반 토큰으로 축소한다.
4. 더보기, 빈 사진 시트, 지도 상점에서 카드 중첩과 중복 강조를 먼저 줄인다.
5. 장소 카드와 문서 화면의 정보 밀도를 조정한다.
6. 표준 `LicensePage`처럼 재작성 위험이 큰 영역은 마지막에 판단한다.
